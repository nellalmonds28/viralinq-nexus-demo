# ViraLinq — NEXUS PRIME Independent Demo

A standalone, responsive, single-page ViraLinq concept website for a **safe engineering delivery exercise**.

## Run locally

Open `index.html` in any modern browser. No dependencies, build, credentials, server, or API access are required.

## Test checklist

1. Open the page on desktop and at 390px mobile width.
2. Verify navigation links jump to the appropriate sections.
3. Select each visitor intent: **See the work**, **Collaborate**, **Book a session**.
4. Verify recommendation title and description change appropriately and `aria-pressed` follows selection.
5. Click **Simulate action** and verify the local confirmation message appears.
6. Verify keyboard navigation and visible focus styles.
7. Verify no network requests or data writes occur from the demo interaction.

## Security and scope

- All names and profiles are synthetic.
- No login, database, payment, Stripe, analytics, or customer messaging integration.
- No production feature flags or deployment settings are changed.
- Features are **concept previews**, not production availability claims.
- This repository is intentionally separate from `ViraLinq-Labs/NEXUS` and `viralinq/viralinq`.

## Publish via GitHub Pages

In the new repository, open **Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save**. Pages availability depends on repository visibility and account plan. Publishing is a separate action; this package does not enable it.

## NEXUS validation boundaries

A successful file commit and Pages publication would demonstrate GitHub delivery and static hosting only. It would not establish NEXUS CTO identity attribution, authorization to mutate NEXUS, or production acceptance for ViraLinq.
